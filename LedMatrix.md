# 📋 ТЕХНИЧЕСКОЕ ЗАДАНИЕ: Модуль `LightBridge` v0.1

> **Цель**: Создать минимальный работоспособный модуль для управления iPIXEL-панелью на основе метрик медитации/концентрации.  
> **Приоритет**: Простота > Функциональность > Красота.  
> **Язык**: Python 3.10+  
> **Интеграция**: Существующее приложение (метрики) + iPIXEL-панель (свет).  
> **Реализация в этом репозитории**: см. [`docs/light-ipixel.md`](docs/light-ipixel.md) (PoC: `MetricsLightBridge`, `light.intent`, BLE-воркер, ручной RGB, повторы connect). **Этап A (без AI)**: JSON-правила AUTO (`NSP_LIGHT_AUTO_RULES_PATH`), лог смены цвета в файл (`NSP_LIGHT_INTENT_LOG`) — см. ту же доку. Отдельный пакет `lightbridge/` из раздела 5 ниже — дорожная карта, не обязательная структура каталогов.

## 🎯 1. Функциональные требования (что должен делать модуль)

### 🔹 Базовый функционал (MVP — Minimum Viable Product)
```
✅ Подключение к iPIXEL-панели по BLE (MAC-адрес задаётся в конфиге)
✅ Приём метрик в формате: {"attention": 0-100, "meditation": 0-100, "timestamp": float}
✅ Три режима управления:
   • MANUAL: прямое управление цветом/яркостью через команды
   • AUTO: простые правила "если метрика > X → включить паттерн Y"
   • AI: передача метрик во внешнюю модель (Ollama/локальная) → получение параметров света
✅ Отправка команд на панель:
   • Заливка одним цветом (solid)
   • Плавное изменение яркости (fade)
   • Простая пульсация (pulse) — изменение яркости по синусу
✅ Логирование: что отправлено на панель, с какими параметрами
✅ Обработка ошибок: потеря соединения, таймауты, некорректные данные
```

### 🔹 НЕ входит в MVP (отложить на v0.2+)
```
❌ Сложные анимации (волны, градиенты, текст)
❌ Визуальный редактор паттернов
❌ Экспорт сценариев в ESP32
❌ Синхронизация с аудио (цветомузыка)
❌ Мультипанельное управление
```

## 📥 2. Входные данные: формат метрик

Модуль должен принимать метрики **одним из способов** (настраивается в конфиге):

### Вариант А: WebSocket (предпочтительно)
```json
// Сообщение от основного приложения
{
  "type": "metrics_update",
  "payload": {
    "attention": 72.5,
    "meditation": 45.2,
    "timestamp": 1774148400.123
  }
}
```

### Вариант Б: Файл (для отладки)
```json
// metrics.json — обновляется основным приложением
{
  "attention": 72.5,
  "meditation": 45.2,
  "timestamp": 1774148400.123
}
```

### Вариант В: Прямой вызов функции (для тестов)
```python
# В основном приложении
from lightbridge import process_metrics
process_metrics(attention=72.5, meditation=45.2)
```

> ⚙️ **Конфигурация источника** (`config.json`):
> ```json
> {
>   "metrics_source": "websocket",  // или "file", "function"
>   "websocket_url": "ws://localhost:8765",
>   "file_path": "./metrics.json",
>   "poll_interval_ms": 100
> }
> ```

## 📤 3. Выходные данные: команды на iPIXEL

Модуль отправляет на панель **только то, что поддерживает `pypixelcolor`** :

| Команда | Параметры | Пример использования |
|---------|-----------|---------------------|
| `set_brightness(level)` | `level: 1-100` | Плавное изменение общей яркости |
| `fill_solid(color)` | `color: (R,G,B)` | Заливка всей панели одним цветом |
| `send_image(pil_image)` | `PIL.Image` в режиме RGB | Для будущих сложных паттернов |
| `clear()` | — | Очистка панели (чёрный) |

> 🎨 **Цветовые пресеты** (задаются в конфиге, можно расширять):
> ```json
> {
>   "presets": {
>     "calm_blue": [100, 150, 255],
>     "focus_white": [255, 255, 200],
>     "balance_teal": [150, 200, 180],
>     "deep_purple": [120, 80, 200]
>   }
> }
> ```

## ⚙️ 4. Режимы работы: логика преобразования «метрики → свет»

### 🔹 Режим MANUAL
```
• Управление через прямые команды (для тестов и отладки)
• Пример команды: {"action": "fill_solid", "color": [255,255,255], "brightness": 50}
• Игнорирует входящие метрики
```

### 🔹 Режим AUTO (правила)
```
• Простая логика "если-то", настраиваемая в конфиге:
{
  "auto_rules": [
    {
      "condition": "meditation > 70",
      "action": "fill_solid",
      "color_preset": "calm_blue",
      "brightness": 40,
      "animation": "pulse",
      "animation_speed": 0.5
    },
    {
      "condition": "attention > 70",
      "action": "fill_solid",
      "color_preset": "focus_white",
      "brightness": 70,
      "animation": "pulse",
      "animation_speed": 2.0
    }
  ]
}
```
> 📝 **Правила проверяются по порядку**, выполняется первое совпадение.  
> 🔄 **Частота проверки**: 1-10 Гц (настраивается).

### 🔹 Режим AI (интеграция с Ollama)
```
• Метрики упаковываются в промпт и отправляются в локальную модель:
{
  "model": "llama3.2",  // или другая, настроенная в Ollama
  "prompt": "Медитация: 45, Концентрация: 72. Предложи параметры света: яркость (1-100), цвет (RGB), паттерн (solid/pulse). Ответь только JSON."
}
```
• Ожидается ответ в строгом формате:
```json
{
  "brightness": 55,
  "color": [150, 200, 180],
  "pattern": "pulse",
  "speed": 1.2
}
```
• Таймаут ответа: 2 секунды. При ошибке — fallback на AUTO-режим.

> ⚙️ **Конфигурация AI** (`config.json`):
> ```json
> {
>   "ai_mode": {
>     "enabled": true,
>     "ollama_url": "http://localhost:11434/api/generate",
>     "model": "llama3.2",
>     "timeout_sec": 2,
>     "fallback_to_auto": true
>   }
> }
> ```

## 🔌 6. API модуля (публичный интерфейс)

```python
# core/bridge.py
class LightBridge:
    def __init__(self, config_path: str = "config.json"):
        """Загрузка конфига, инициализация компонентов"""
        
    async def start(self):
        """Подключение к панели + запуск цикла обработки метрик"""
        
    async def stop(self):
        """Корректное отключение: очистка панели, закрытие BLE"""
        
    def set_mode(self, mode: Literal["manual", "auto", "ai"]):
        """Переключение режима на лету"""
        
    # Для интеграции с основным приложением:
    def feed_metrics(self, attention: float, meditation: float, timestamp: float = None):
        """Прямая передача метрик (если источник = 'function')"""
```

> 🔄 **Цикл обработки** (внутри `start()`):
> 1. Получить свежие метрики из источника
> 2. В зависимости от режима: преобразовать в параметры света
> 3. Отправить команды на панель (только если параметры изменились)
> 4. Записать в лог: `{"in": {...}, "out": {...}, "mode": "auto"}`
> 5. Подождать `poll_interval_ms` и повторить

## ✅ 8. Критерии успеха (Acceptance Criteria)

Модуль считается рабочим, если:

```
✅ При запуске подключается к панели по указанному MAC-адресу
✅ В режиме MANUAL: команда {"action":"fill_solid","color":[255,0,0]} заливает панель красным
✅ В режиме AUTO: при meditation>70 панель становится синей и пульсирует (проверяется визуально)
✅ В режиме AI: при отправке метрик в Ollama приходит валидный JSON, параметры применяются к панели
✅ При обрыве BLE-соединения модуль логирует ошибку и пытается переподключиться (3 попытки)
✅ Все действия логируются в файл lightbridge.log с таймстампами
✅ Конфигурация меняется без правки кода (только config.json)
```

### Сценарий 1: «Первый свет»
```

```

Тогда: панель становится #6496FF и плавно пульсирует с частотой 0.5 Гц
```

### Сценарий 3: «AI-интерпретация»
```
Дано: режим = AI, Ollama запущен с моделью
Когда: получены метрики {meditation: 40, attention: 80}
Тогда: 
  1. Сформирован промпт, отправлен в Ollama
  2. Получен валидный JSON с параметрами
  3. Параметры применены к панели
  4. В логе запись: "AI response parsed: brightness=65, pattern=pulse"
```

## 💡 11. Подсказки для Cursor (чтобы избежать типичных ошибок)

```
❗ Важные нюансы реализации:

1. BLE на Windows требует дополнительных шагов:
   - Убедиться, что установлен драйвер Bluetooth
   - Использовать asyncio-совместимые вызовы (bleak — асинхронный)

2. iPIXEL-панель имеет ограничение на частоту команд:
   - Не отправлять команды чаще 10-20 раз в секунду
   - Буферизировать изменения: отправлять только если параметры изменились

3. Ollama может отвечать медленно:
   - Всегда ставить таймаут (2 сек)
   - Парсить ответ строго: если не валидный JSON — использовать fallback

4. Цвета в iPIXEL: порядок каналов — RGB (не GRB, как в WS2812B!)

5. Логирование: использовать отдельный файл, чтобы не засорять консоль основного приложения

6. Конфигурация: все «магические числа» (частоты, пороги, цвета) выносить в config.json
```
